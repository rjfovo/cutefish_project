# 桌面壁纸修复与视频壁纸实现 —— 技术记录

> 最后更新：2026-08-08
> 本文记录桌面壁纸黑屏问题的完整排查、根因分析与架构修复（分层桌面 → 单一桌面窗口），
> 以及视频壁纸功能（设置端 + 桌面渲染端）的实现。

---

## 1. 背景与问题现象

### 1.1 历史问题
- 重构前（`filemanager -d` 单一桌面进程）：壁纸显示正常，但桌面右键菜单存在 5 个问题（新建文件夹失败、打开终端无反应、设置壁纸打不开、菜单方角、菜单不弹出）；
- 为解决菜单问题进行了重构（`filemanager -d` → `cutefish-desktop` 独立进程 + `libcutefish-filemodel` 共享库，见《桌面进程重构与技术记录.md》）。

### 1.2 重构后新问题
- **桌面整屏黑屏**（壁纸不显示、图标层内容异常）；
- 测试服务器为 **VMware 虚拟机**（`glx: failed to create dri3 screen`，GLX 无 alpha 通道）。

---

## 2. 根因分析（三层）

### 2.1 第一层：重构引入的代码缺陷

| 缺陷 | 现象 | 修复 |
|---|---|---|
| **FishUI 主题循环依赖**：`QT_QUICK_CONTROLS_STYLE=FishUI` 使 QtQuick.Controls 的 primary style 指向 FishUI 模块自身；`FishUI.MenuItem`（继承 `T.MenuItem`）解析时形成自循环 | `Type FishUI.MenuItem unavailable` → 桌面 Main.qml 编译失败 | style 改为 `fish-style`（文件系统模块）；fish-style 菜单类去掉 `import FishUI` |
| **Qt6 QQuickWindow 默认无 alpha 缓冲**：`session/main.cpp` 设了 `setDefaultAlphaBuffer(true)`，desktop/desktop-background 漏了 | 透明窗口背景不透明黑 | 两个桌面进程加 `setDefaultAlphaBuffer(true)` |
| **libFishUI.so 漏链接 libX11-xcb**：`windowhelper.cpp` 用 `XGetXCBConnection` | 右键菜单弹出即崩溃（`undefined symbol`） | fishui CMakeLists 链接 `X11::XCB` |
| **进程重复启动**：processmanager 定时器 + settings-daemon D-Bus 双触发 | 壁纸层/图标层各跑两份，最后启动的壁纸层被叠压 | `startDesktopProcess` 加幂等保护 |

### 2.2 第二层：VMware 环境限制
- VMware 虚拟 GPU 的 X11 GLX 无 alpha 通道；
- Qt RHI OpenGL 渲染的透明区域 alpha 恒为 255（GLX / llvmpipe / EGL 均实测无效）；
- 只有 `QT_QUICK_BACKEND=software`（QImage 带 alpha 上传）透明合成正常。

**但注意**：GLX 无 alpha 不是黑屏的"根因"——重构前同样环境壁纸正常（因为壁纸 Image 铺满同一窗口，掩盖了透明缺陷）。

### 2.3 第三层（真正根因）：分层桌面架构与软件渲染的死结
重构后拆成"透明图标层 + 独立壁纸层"两个全屏窗口，在这台环境（需软件渲染兜底）下形成**结构性死结**：
- 软件渲染依赖窗口 **expose 事件**才开始渲染；
- 两个全屏窗口叠加，**下面那个永远被完全遮挡 → 收不到 expose → 不渲染 → 黑**；
- 上面的窗口能渲染，但内容（壁纸或黑底）会**盖住下面那个**；
- 实测堆叠：**壁纸层被放在图标层之上**（启动顺序导致），壁纸渲染成功即盖住图标层 → **"壁纸与菜单互斥"**（壁纸显示时菜单被压住；壁纸黑时菜单浮出）。

---

## 3. 架构决策：分层 → 单一桌面窗口

**放弃"透明图标层 + 独立壁纸层"分层架构**，改为**单一不透明桌面窗口**（壁纸 + 图标 + 右键菜单同窗口）：

```
cutefish-desktop（唯一桌面进程，不透明 GL 渲染）
┌───────────────────────────────┐
│ 壁纸层（Image / 纯色 / 视频）│  z 最底、铺满、不透明
│ 图标层（FolderGridView）      │  盖在壁纸上面
│ 右键菜单（FileContextMenu）   │  菜单 Popup 在唯一窗口内，无层级竞争
└───────────────────────────────┘
```

**收益**：
- 不透明窗口走 GL 渲染：不依赖 alpha、不依赖软件渲染、不依赖 expose、不依赖 KWin 窗口层级 → 环境无关，彻底解决黑屏/菜单互斥/菜单文字问题；
- 视频壁纸天然可承载（壁纸区换 Video 元素即可，不透明）。

**改动**：
- `desktop/desktopview.cpp`：去掉 `setColor(transparent)` / alpha format / 定期 update；窗口改不透明；
- `desktop/main.cpp`：去掉 `QT_QUICK_BACKEND=software` 与 `setDefaultAlphaBuffer`；
- `desktop/qml/desktop/Main.qml`：壁纸层并入（图片/纯色/视频三模式）；
- `core/session/processmanager.cpp`：停用 `cutefish-desktop-background`；
- 移除 `/etc/xdg/autostart` 中两个桌面进程的 autostart（避免重复启动）。

## 4. 视频壁纸功能

### 4.1 设置端（settings）
- `src/background.h/.cpp`：
  - 新增 `videos` 属性（扫描 `/usr/share/backgrounds/cutefishos` + `~/Videos` 下视频）；
  - `setVideoBackground(path)`：D-Bus 设 `wallpaper` + `backgroundType=2`；
  - `pickImage()/pickVideo()`：`QFileDialog` 选本地图片/视频（**需 QApplication**）；
- `src/qml/Wallpaper/Main.qml`：Background 三个标签 **Picture / Color / Video**；新增 **Add Picture… / Add Video…** 按钮；视频网格（图标 + 文件名 + 选中态）；
- `src/application.h/.cpp`：`QGuiApplication` → **`QApplication`**（QFileDialog 是 QWidget 类，QGuiApplication 下会崩溃）。

### 4.2 桌面渲染端（desktop）
- `qml/desktop/VideoWallpaper.qml`（新建）：视频壁纸组件
  - `fillMode: PreserveAspectCrop` 全屏铺满、`autoPlay`、**`muted: true`**（壁纸无需音频，省解码 CPU）；
  - **无缝循环**：接近结尾 `setPosition(0)`（seek）替代 `stop→play`，避免循环点闪烁；
  - **独立成文件**：仅在 `backgroundType=2` 时由 Main.qml 的 Loader 动态加载，避免无 Qt Multimedia 的系统整个桌面 QML 编译失败；
- `qml/desktop/Main.qml`：`backgroundLoader` 支持三模式（`0`图片 / `1`纯色 / `2`视频）；
- `CMakeLists.txt` / `qml.qrc`：Qt Multimedia 改为**可选依赖**（有则链接，无则静态壁纸仍正常）。

### 4.3 打包配置
- `desktop/debian/control`：
  - Build-Depends 加 `qt6-multimedia-dev`；
  - Depends 加 `qml6-module-qtmultimedia`、`libqt6multimedia6`、`gstreamer1.0-plugins-good`、`gstreamer1.0-libav`。

## 5. 其他修复

### 5.2 登出（logout）黑屏卡住
- **现象**：点击右上角关闭按钮 → 登出后 sddm 不显示登录界面，黑屏卡住；
- **根因**：`ProcessManager::logout()` 调用了 login1 的 `Terminate`（系统级强制终止会话）。sddm-helper 把会话进程异常退出误判为 `Process crashed`（`sddm-helper crashed (exit code 1)`），于是不启动 greeter → 黑屏；
- **修复**（`core/session/processmanager.cpp`）：去掉 `Terminate`，让会话进程正常 `QCoreApplication::exit(0)` 退出 → sddm 识别为正常登出并启动 greeter；
- **验证**：登出后 `Greeter session started successfully`，登录界面正常显示。

### 5.3 锁屏视频壁纸黑屏
- **现象**：壁纸设为视频时，锁屏界面背景全黑；
- **根因**：锁屏 `LockScreen.qml` 用 `Image` 加载 `System.Wallpaper.path`，视频文件无法用 Image 加载 → 黑屏；
- **修复**（`screenlocker`）：
  - 新建 `qml/VideoWallpaper.qml`（独立文件，`muted` + seek 无缝循环，仅视频模式加载）；
  - `LockScreen.qml` 背景层支持三模式：图片（type 0，Image + FastBlur）/ 纯色（type 1，Rectangle）/ 视频（type 2，Loader 加载 VideoWallpaper）；
  - `debian/control` 补 `qml6-module-qtmultimedia` / `libqt6multimedia6` 依赖；
- **验证**：锁屏显示动态视频（黑屏占比 92% → 9%）。

### 5.4 视频壁纸动态切换白屏
- **现象**：设置中 Add Video 选视频后，桌面变白屏；切换 Color / Video 标签后才显示；
- **根因**（两个）：
  - `VideoWallpaper.qml` 用 `setPosition(0)` 做无缝循环 —— Qt6 的 `MediaPlayer.position` 是属性，`setPosition()` 未定义，`ReferenceError` 中断处理；
  - 动态改变 `Video.source` 时，`autoPlay` 只对初始 source 生效，**不会自动播放** → 白屏；
- **修复**：
  - `setPosition(0)` → `position = 0`（desktop + screenlocker 两个 VideoWallpaper.qml）；
  - 新增 `onSourceChanged: play()`：source 变化时手动播放；
  - 桌面 `videoWallpaperComp` 的壁纸路径同步改用 `Connections + 直接赋值`（比 `onLoaded` 里的 `Qt.binding` 更可靠）；
- **验证**：图片 → Video 标签 → Add Video，视频立即显示（不再白屏）。

### 5.5 build_code.sh 清理交互提示
- `script/build_code.sh` 的 `clean()`：`debuild -- clean` → `fakeroot debian/rules clean`；
- 原因：`debuild`（devscripts）clean 前检查源包文件（`.orig.tar.*`），缺失时交互弹 `continue anyway? (y/n)` 卡住脚本（已确认 `/usr/bin/debuild:1010`）。

### 5.2 视频壁纸性能（VMware 软解）
- 1080p 视频在无 GPU 硬解的 VMware 下软件解码 CPU 占用高（实测 38.5% → 静音后 19.7%）；
- 建议：VMware 测试环境用 ≤720p 视频；真实硬件（硬解）无此限制。

## 8. 遗留事项

- **视频壁纸扫描范围**：当前扫描 `/usr/share/backgrounds/cutefishos` + `~/Videos`，用户放在其他目录（如 `~/`）的视频需通过 Add Video 选择；可扩展扫描范围或记录最近选择；
- **高分辨率视频自动降采样**：Qt Multimedia 不暴露解码分辨率控制，VMware 软解高分辨率耗 CPU；如需可加 ffmpeg 预转码逻辑；
- **Wayland 迁移**：与本文无关的独立议题，本次修复在 X11 下完成。

## 9. 设置程序圆角样式修复（fish-style 与 FishUI.Window 冲突）

### 9.1 背景
设置程序迁移 Qt6 后控件变方角：原 `QT_QUICK_CONTROLS_STYLE=FishUI` 因循环依赖失效
（fish-style 主题文件 import FishUI 与 FishUI 模块 depends QtQuick.Controls 互依赖 → 解析失败）。
已通过 fish-style 全部控件去 FishUI 化 + `ThemeValues.js` 提供常量解决。

### 9.2 新问题
启用 fish-style 后设置程序**窗口全透明无内容**（QML 无错误、渲染循环已启动但内容不上屏）。

### 9.3 定位过程（最小程序二分）
| 测试 | 结果 |
|---|---|
| ApplicationWindow + Button/TabBar/Label + fish-style | ✅ 正常 |
| ApplicationWindow(透明) + fish-style | ✅ 正常 |
| 纯 QtQuick.Window + fish-style | ✅ 正常 |
| FishUI.Window + fish-style（含纯 Rectangle、无 Controls 控件） | ❌ 全黑 |
| FishUI.Window + `windowRadius: 0` + fish-style | ✅ 正常 |
| FishUI.Window + 圆角 + fish-style（FishUI.Window 内部注释掉 `import QtQuick.Controls`） | ✅ 正常 |

### 9.4 根因
**FishUI.Window（QtQuick.Window）内部 `import QtQuick.Controls 6.0` + `QT_QUICK_CONTROLS_STYLE=fish-style`
会导致该 QtQuick.Window 的整个场景内容不上屏（窗口全透明）**。
机制：import QtQuick.Controls 时初始化 QtQuick.Controls 主题系统（fish-style），
与 QtQuick.Window（非 ApplicationWindow）的渲染产生冲突。
（应用层 ApplicationWindow 正常；应用层 QtQuick.Window 正常——必须是 FishUI.Window 内部 import 才触发。）

### 9.5 修复
`fishui/src/controls/Window.qml`：移除 `import QtQuick.Controls 6.0`（本文件不使用任何
QtQuick.Controls 控件，窗口头按钮为 FishUI.Item 组件）。libFishUI.so 重编部署后，
所有使用 FishUI.Window 的应用自动修复。

### 9.6 验证
设置程序启用 fish-style 后：侧边栏 + 内容区 + TabBar 圆角标签正常显示，无 QML 错误。

## 10. 桌面壁纸偶发黑屏修复（QtMultimedia FFmpeg 插件竞态崩溃）

### 10.1 现象
重构合并壁纸到 desktop 后，**自动登录时偶发黑屏**（无壁纸、无图标、无 dock）。
`~/.xsession-errors` 报 `DE component failed to start: "cutefish-desktop" exit code: 11`（SIGSEGV），
历史上累计失败 15 次。手动启动 cutefish-desktop 则完全正常。

### 10.2 定位过程
| 步骤 | 方法 | 结论 |
|---|---|---|
| 1 | 查日志 | cutefish-desktop 启动即段错误（exit 11），无 QML 错误输出 |
| 2 | 手动启动 | 壁纸正常 → 问题只在自动登录启动场景 |
| 3 | gdb 运行 | 不崩溃（时序被拖慢）→ 偶发竞态 |
| 4 | gdb wrapper + 循环重启会话 | 第 2 次重启抓到 core（241MB） |
| 5 | gdb 分析 core | 崩溃在 `libffmpegmediaplugin.so`（Qt Multimedia FFmpeg 后端插件）工作线程 |

崩溃 backtrace 关键帧：
```
#0  libffmpegmediaplugin.so
#1  QObject::event(QEvent*)
#12 QThread::exec()     ← QtMultimedia 工作线程
```

### 10.3 根因
`desktop/qml/desktop/Main.qml` 的 `videoWallpaperComp` Loader **漏了 `active` 条件**，
无条件加载 `VideoWallpaper.qml`（顶部 `import QtMultimedia`）→ 即使背景是图片/纯色，
QtMultimedia 的 FFmpeg 插件也会被初始化。自动登录时多个桌面组件并发启动 + VMware
无音频/无硬件解码环境下，FFmpeg 插件初始化偶发段错误 → desktop 崩溃 → 黑屏。
（对比：`screenlocker/LockScreen.qml` 用 `active: wallpaper.type === 2` 条件加载，写法正确。）

### 10.4 修复
1. **治本**：`desktop/qml/desktop/Main.qml` Loader 加 `active: settings.backgroundType === 2`，
   仅视频壁纸模式加载 QtMultimedia，图片/纯色模式完全不初始化 FFmpeg 插件。
2. **兜底**：`core/session/processmanager.cpp` 抽 `startDesktopComponent()`；
   cutefish-desktop 崩溃（CrashExit）时 3 秒后自动重启，连续崩溃 5 次停止；
   启动成功且存活 60 秒后重置崩溃计数。

### 10.5 验证
- 手动 kill cutefish-desktop → 5 秒内 ProcessManager 自动拉起 ✅
- 连续多次重启会话：desktop 均正常启动、壁纸/图标/dock 正常显示、无 core dump ✅
