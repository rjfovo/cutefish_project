# 启动/登录/关机阶段终端界面消除 —— 技术记录

> 最后更新：2026-08-15
> 现象：GRUB → 登录界面、登录界面 → 桌面、关机/重启过程中会短暂出现 Linux
> 文本控制台（kernel log / getty login 提示），产品观感不成熟。

## 1. 根因

| 阶段 | 根因 |
|---|---|
| GRUB 阶段 | `/etc/default/grub` 由 calamares `grubcfg` 写成 `GRUB_TERMINAL_OUTPUT='console'`，GRUB 菜单与 `Loading Linux/initrd` 信息走 VGA 文本控制台。 |
| GRUB → SDDM | 未安装 `plymouth` 引擎，只有 `cutefish-plymouth-theme` 主题；内核参数只有 `quiet` 没有 `splash`，initramfs 中没有 plymouth，启动日志直接落在 tty1。 |
| Plymout → SDDM 交接 | `getty@tty1` 默认启用。Plymouth 退出后 tty1 是活动 VT，若 getty 在上面会闪现 login 提示；SDDM 从下一空闲 VT（实测 vt2）启动 X，期间存在控制台可见窗口。 |
| 关机/重启 | 未安装 plymouth，systemd 停机消息直接显示在控制台。 |

## 2. 业界通用方案（Debian/Ubuntu 同款）

1. **GRUB 图形模式**：`GRUB_TERMINAL_OUTPUT=gfxterm`，`GRUB_GFXMODE=auto`，
   `GRUB_GFXPAYLOAD_LINUX=keep`，可选 `GRUB_BACKGROUND` 壁纸。
2. **Plymouth bootsplash**：安装 `plymouth` 引擎 + 发行版主题，内核参数
   `quiet splash`；Plymouth 的 `plymouth-start`、`plymouth-quit` 与
   `plymouth-reboot/poweroff/halt` 分别覆盖启动和关机画面。
3. **DM 与 VT 交接**：让显示管理器与 `plymouth-quit-wait` 正确排序；关闭
   tty1 getty，避免 getty login 提示闪现。SDDM 官方 unit 注释也说明了
   `After=plymouth-quit.service` / `Conflicts=plymouth-quit-wait.service`
   两种配合方式。
4. **隐藏光标**：内核参数 `vt.global_cursor_default=0`，避免黑屏阶段闪烁光标。

## 3. 本项目修复

- `cutefish/code/plymouth-theme`
  - `debian/control` 增加 `Depends: plymouth, plymouth-label`，装主题自动装引擎。
  - 主题从静态 logo 升级为动态过场动画，详见
    《Plymouth开机关机动画设计.md》。
- `cutefish/code/calamares-settings`
  - `modules/grubcfg.conf`：`GRUB_TERMINAL_OUTPUT=gfxterm`、`GRUB_GFXMODE=auto`、
    `GRUB_GFXPAYLOAD_LINUX=keep`、Cutefish 壁纸 `GRUB_BACKGROUND`；
    `kernel_params` 为
    `quiet loglevel=2 systemd.show_status=0 vt.global_cursor_default=0`，
    检测到 plymouth 后自动追加 `splash`。`loglevel=2` 可隐藏 VMware 上常见的
    `ACPI [Firmware Bug]`、`piix4_smbus` 等 warning/error 控制台输出；
    `systemd.show_status=0` 关闭关机/启动时的 unit 状态输出；journal 中仍完整保留。
  - `settings.conf`：在 `initramfs` 前增加 `plymouthcfg`。
  - 新增 `modules/plymouthcfg.conf`：默认主题 `cutefish-logo`。
  - 新增 `modules/services-systemd.conf`：安装时 `disable getty@tty1`、
    `enable sddm`。
- `cutefish/code/core/session`（Session Splash）
  - 自动登录时 SDDM 不会显示 greeter，X ready 到桌面第一帧之间原本会黑屏。
  - 新增 `splash.qml` + `splashwindow.cpp/h`：cutefish-session 启动时先显示
    一张与 Plymouth/SDDM 同源的 boot-background 全屏过渡图，桌面进程启动后
    3 秒淡出，12 秒超时兜底。
  - `ProcessManager` 桌面组件启动顺序调整：先启动 `cutefish-desktop` 全屏
    壁纸，再启动面板/dock；等待时间从 1000ms 降到 300ms。
- `cutefish/code/sddm-theme`
  - 新增 `src/conf/cutefish-plymouth.conf` 并安装为
    `/usr/lib/systemd/system/sddm.service.d/cutefish-plymouth.conf`：
    SDDM 启动前 `plymouth quit --retain-splash && plymouth --wait`，
    确保 plymouthd 完全退出后再开 X VT，同时保留最后一张开机画面，避免
    开机/关机切换回文本控制台。
- `build_iso/script/patch_grub_quiet.sh`（新增）
  - 修补 Debian `/etc/grub.d/10_linux`：当内核参数含 `quiet` 时不再输出
    `Loading Linux ...` / `Loading initial ramdisk ...`。
  - 当内核参数含 `splash` 且 `GRUB_GFXPAYLOAD_LINUX=keep` 时启用 Debian
    自带的 `vt_handoff` 逻辑，自动追加 `vt.handoff=7`。
- `build_iso/config/10-cutefish-console.conf`（新增）
  - `kernel.printk = 2 4 1 7`：开机后继续把 VT 控制台 loglevel 压在 2，
    防止晚加载驱动（如 `piix4_smbus`）的 warning 重新打到屏幕上。
- `build_iso/config/10-cutefish-systemd-quiet.conf`（新增）
  - `ShowStatus=no`：systemd 的启动/关机 unit 状态不写控制台。
  - `LogTarget=journal-or-kmsg`：正常日志进 journal 文件；journal 停止后
    的最终 kmsg 回退输出由 `kernel.printk=2` 过滤，不会落到可见 VT。
  - 安装位置：`/etc/systemd/system.conf.d/10-cutefish-quiet.conf`。
- `build_iso/script/patch_plymouth_units.sh`（新增）
  - 保留 Plymouth 正常的 `--attach-to-session` VT 交接行为，但给所有
    plymouthd 注入一个极小的 `LD_PRELOAD` 拦截库
    （`plymouth-no-status.c` / `.hook`）。
  - 该库只吞掉 Plymouth 发给 PID 1 的 `SIGRTMIN+20/21`；这两个信号会把
    `ShowStatus` 临时重新打开，导致 `[ OK ] Finished plymouth...` 这类
    状态行在主题出现前/结束后打到控制台。
  - 同一拦截库会通过 initramfs hook 打进 initrd，因此 initramfs 阶段启动
    的 plymouthd 也不会重新开启 systemd 状态输出。
- `build_iso/script/patch_plymouth_persistent.sh`（新增）
  - 开机后不再 `plymouth quit`；daemon 持续存活，SDDM 的 Xsetup 调用
    `plymouth deactivate`，关机时 Xstop 调用 `plymouth reactivate`。
  - 关机/重启服务复用已有 daemon，只执行 `change-mode + show-splash`。
  - `plymouth-quit/quit-wait` 被中和；新增 SDDM 失败时的真实退出兜底单元。
- `build_iso/script/patch_initramfs_progress.sh`（新增）
  - initramfs 关键节点通过 `plymouth system-update --progress` 上报：
    10/40/65/85/92，进度条从 root fsck 阶段开始就真实前进。
- `build_iso/script/patch_initramfs_quiet.sh`（新增）
  - initramfs-tools 的 `_checkfs_once()` 使用 `logsave` 执行 fsck，而
    `logsave` 会同时把输出复制到 stdout（可见控制台），这就是
    `/dev/sda2: clean, ...` 的来源。
  - 修补 quiet 分支，给 `logsave ... >/dev/null`；日志仍完整写入
    `/run/initramfs/fsck.log`，只是不再显示到 tty。
- `script/create_iso/*`
  - live/install chroot 基础包显式安装 `plymouth`、`plymouth-label`。
  - 安装后执行 `patch_grub_quiet.sh`、`patch_plymouth_units.sh`、
    `patch_initramfs_quiet.sh`、`plymouth-set-default-theme cutefish-logo`
    与 `update-initramfs -u -k all`。
  - 关闭 `getty@tty1`，复制 SDDM drop-in。
  - `create_iso.sh`：GRUB 改为 gfxterm + Cutefish 壁纸背景；内核参数
    `boot=live quiet loglevel=2 systemd.show_status=0 splash vt.global_cursor_default=0 vt.handoff=7`。
- 重新构建并更新了 `build_iso/package/cutefish/` 中的
  `cutefish-plymouth-theme_0.5-6`、`cutefish-calamares-settings_1.0.0-5`、
  `cutefish-sddm-theme_0.5-3`、`cutefish-wallpapers_0.5-1` 四个 deb。

## 4. 已安装系统（测试服务器）处理

对 `192.168.118.132` 执行并验证：

```bash
apt-get install -y plymouth plymouth-label
plymouth-set-default-theme cutefish-logo
# 修改 /etc/default/grub：
#   GRUB_TERMINAL_OUTPUT=gfxterm
#   GRUB_GFXMODE=auto
#   GRUB_GFXPAYLOAD_LINUX=keep
#   GRUB_BACKGROUND=/usr/share/backgrounds/cutefishos/default.jpg
#   GRUB_CMDLINE_LINUX_DEFAULT="quiet splash vt.global_cursor_default=0 resume=..."
update-initramfs -u -k all
grub-mkconfig -o /boot/grub/grub.cfg
cp /boot/grub/grub.cfg /boot/efi/EFI/cutefish/grub.cfg   # 该系统实际从该副本启动
systemctl disable getty@tty1.service
# 添加 /etc/systemd/system/sddm.service.d/cutefish-plymouth.conf（与仓库配置相同）
```

## 5. 验证结果

- `/proc/cmdline`：`... quiet loglevel=2 splash vt.global_cursor_default=0 vt.handoff=7 resume=...`。
- `/proc/sys/kernel/printk`：`2 4 1 7`；`Firmware Bug` / `piix4_smbus`
  仍记录在 journal，但不再输出到可见 VT 控制台。
- `/boot/grub/grub.cfg` 与 EFI 副本中已经 **没有** `Loading Linux ...` /
  `Loading initial ramdisk ...` 两个 echo。
- `lsinitramfs`：已包含 `usr/bin/plymouth`、`plymouthd`、
  `cutefish-logo` 主题、drm/frame-buffer renderer。
- GRUB 生成的 `/boot/grub/grub.cfg` 与 EFI 副本：
  `terminal_output gfxterm`、Cutefish 壁纸背景、`gfxpayload=keep`。
- `getty@tty1`：disabled/inactive；SDDM 正常在 vt2 启动，tty1 无 login 提示。
- 重启日志：`plymouth-start.service` 正常；上一次关机时
  `plymouth-reboot.service` 正常启动，关机画面覆盖文本停机信息。
