## 1. 分层桌面架构

桌面由**两个进程**分层组成，均为 `_NET_WM_WINDOW_TYPE_DESKTOP` 桌面窗口，
KWin 会将它们都放置在窗口堆叠的最底层：

```
┌─────────────────────────────────────────────┐
│ 普通应用窗口                                │
├─────────────────────────────────────────────┤
│ cutefish-dock                               │
├─────────────────────────────────────────────┤
│ cutefish-filemanager -d（图标 + 菜单层）    │ 背景透明，只画图标与右键菜单
├─────────────────────────────────────────────┤
│ cutefish-desktop-background（壁纸层）       │ 壁纸 / 纯色 / 暗色调暗
└─────────────────────────────────────────────┘
```

### 职责与启动
- **壁纸层** `cutefish-desktop-background`：负责壁纸、纯色背景、暗色模式调暗。
  由 `core/session/processmanager.cpp` 启动，先启动（在下层）。
- **图标/菜单层** `cutefish-filemanager -d`：负责桌面图标（FolderGridView）与右键菜单。
  由同一进程管理器启动，后启动（在上层），窗口背景透明。
- `filemanager` 桌面窗口通过 `desktopLayerOnly = true` 关闭自身壁纸渲染（`qml/Desktop/Main.qml`、
  `qml/Desktop/Wallpaper.qml` 中 `visible: !desktopLayerOnly`），避免与壁纸层重复绘制。

### 为什么这样拆
- 迁移 Qt6/KWin6 后，旧版 filemanager 桌面窗口类型设置错误（`setFlags` 替换了全部 flags、
  仅依赖 `_q_platform_WindowType` hack），导致开机弹出普通窗口。
- 拆分后壁纸层已独立且稳定；图标/菜单层使用与壁纸层**相同**的窗口类型方案：
  `setFlags(flags() | ...)` + `setProperty("_NET_WM_WINDOW_TYPE", "...DESKTOP")` +
  `KX11Extras::setType(winId(), NET::Desktop)` + `KX11Extras::setOnAllDesktops(...)`，
  并在窗口句柄创建后、`show()` 前设置，再延迟 1 秒显示。
- 分层的好处：任一层崩溃，另一层仍能兜底（壁纸不黑、图标不丢）。

### 关键文件
| 文件 | 说明 |
|---|---|
| `filemanager/desktop/desktopview.cpp` | 桌面窗口：类型、透明背景、分层标记 |
| `filemanager/desktop/desktop.cpp` | 多屏管理、延迟显示 |
| `filemanager/qml/Desktop/Main.qml` | 主屏图标视图 + 右键菜单接入 |
| `filemanager/qml/Desktop/Wallpaper.qml` | 副屏壁纸（分层模式下禁用） |
| `desktop-background/` | 壁纸层独立程序 |
| `core/session/processmanager.cpp` | 会话启动顺序 |

## 2. 统一右键菜单机制

### 设计原则
内容与渲染分离 + **单一 QML 渲染器**（fish-style，圆角/阴影/暗色模式统一）。

- **所有应用菜单统一使用 `FishUI.DesktopMenu`（QML 弹出窗口）+ `FishUI.MenuItem`**
  + `QtQuick.Controls.MenuItem/MenuSeparator`。
- 菜单项外观由 fish-style 统一渲染；一处增强（fishui），全系统菜单受益。
- 系统托盘（StatusNotifierItem / DBusMenu 生态）受协议限制仍使用 C++ `QMenu`，
  但其渲染已通过 `qt-plugins/widgetstyle/basestyle.cpp` 的 `CE_MenuItem` 修复
  （圆角 + 内边距），与 QML 菜单视觉一致。

### 组件清单（fishui）
| 组件 | 作用 |
|---|---|
| `FishUI.DesktopMenu` | 菜单弹出窗口（基于 `MenuPopupWindow`），支持 `popupAt(x,y)` 指定位置弹出 |
| `FishUI.MenuItem` | 统一菜单项：图标/禁用/勾选/快捷键 + **子菜单**（`submenu` 属性，hover/点击右侧展开） |
| `FishUI.MenuManager` | 全局关闭所有打开的菜单（点击菜单项后关闭整个菜单链，含子菜单） |
| `MenuPopupWindow` | C++ 层：弹出定位、屏幕边界、鼠标/触摸事件、菜单链关闭 |

### 触发流程
```
用户右键 → FolderGridView/FolderListView 发出 contextMenuRequested(x, y)
        → 宿主（桌面 Main.qml / 文件管理器 FolderPage.qml）Connections 接收
        → dirModel.updateMenuState()   （刷新 isTrash/rootWritable/hasDir/... 动态状态）
        → FileContextMenu.popupAt(x, y)（弹出统一菜单）
        → 点击菜单项 → 动作（foldermodel Q_INVOKABLE）→ MenuManager.closeAllMenus()
```

### 菜单内容（`filemanager/qml/FileContextMenu.qml`）
桌面与文件管理器**共用同一组件**，菜单项可见性由 `model` 动态状态控制：

- 空区域：新建文件夹 / 新建文档▸(新建文本) / 粘贴 / 全选 / 在终端中打开 / [桌面]更改背景 /
  显示设置 / 显示隐藏文件(勾选) / 属性
- 选中项：还原 / 打开 / 在新窗口中打开 / 打开方式 / 剪切 / 复制 / 移动到回收站 / 删除 /
  重命名 / 在终端中打开 / 设置为壁纸 / 属性

### foldermodel 新增的菜单状态接口
| 属性/方法 | 说明 |
|---|---|
| `isTrash` / `rootWritable` / `hasDir` / `singleSelectedDir` / `canSetWallpaper` | 菜单项可见性/启用状态 |
| `updateMenuState()` | 打开菜单前刷新以上状态并发出 `menuStateChanged` |
| `openDisplaySettings()` | 打开设置→显示器模块（`cutefish-settings -m display`） |
| `openChangeWallpaperDialog()` | 打开设置→壁纸模块（经 session 启动，更可靠） |

### 历史遗留（勿回退）
- `foldermodel.cpp` 中 `openContextMenu()`（C++ QMenu）已**不再被 QML 调用**，
  保留仅作 API 兼容，勿重新启用。
- 若未来要彻底统一（含系统托盘），方向是 Qt QPA 的 `QPlatformMenu`，
  让 C++ `QMenu` 也走 `MenuPopupWindow` 的 QML 渲染——目前 Qt6 支持有限，暂不实施。
